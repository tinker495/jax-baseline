# 실험 설정 작성 규칙

이 지침은 `experiments/configs/`와 모든 하위 디렉터리에 적용한다.
설정 구조와 실행 방법은 [README.md](README.md)를 따른다.

## 학습 효율을 최대화하는 기본값

학습용 YAML은 실험 목적·학습 품질·재현 조건을 유지하면서, 해당 알고리즘과 환경에서
학습 효율을 최대화하도록 설계해야 한다. 충분한 로그 간격, 벌크 학습, 체크포인팅과
장치 내 데이터 유지를 지원 범위에서 적극 활용한다. 신규 설정과 기존 설정 변경 모두에 적용한다.

- `log_interval`을 명시한다. worker 수와 runner의 step 단위를 확인하고, 진단·host 전송·I/O가
  매 env step 또는 update마다 발생하지 않도록 충분한 간격을 둔다. 일반 `dpg`·`qnet`의
  vector rollout은 전체 worker의 transition 기준이다. `worker: 1024`에서
  `log_interval: 102400`은 100 vector steps 간격이다. 디버깅 빈도를 학습 기본값으로 남기지 않는다.
- 벌크 학습을 지원하면 `train_freq`, `gradient_steps`, `max_bulk_updates_per_pulse`를 함께
  조정해 compiled pulse를 활용한다. update 비율·actor/target 갱신 주기·메모리 한도를 확인하고,
  수집과 학습을 묶으면서 생기는 행동 정책 갱신 지연을 평가한다. 지원하지 않는 runner나
  알고리즘에 벌크 옵션을 무조건 추가하지 않는다.
- TD7식 체크포인팅을 지원하면 `use_checkpointing: true`로 수집·학습을 묶는 경로를
  우선 검토한다. 행동 정책 snapshot과 학습 스케줄을 제어하는 기능임을 고려한다.
  체크포인팅이나 벌크 학습을 사용하지 않을 때는 알고리즘 제약·비교 조건·측정 결과 등
  해당 설정의 이유를 YAML 주석에 남긴다.
- 환경·replay backend는 불필요한 CPU↔GPU 왕복을 줄이도록 선택한다. 평가·모델 저장·진단은
  목적에 필요한 빈도로 설정한다. 처리량을 높이기 위해 update 수·학습 예산·평가 의미를
  몰래 바꾸지 않는다. 의도한 변경은 주석에 명시하고 학습 성능까지 검증한다.
- 지원되는 옵션만 사용하며 `base`와 variant override가 합쳐진 최종 값을 확인한다.
  다른 환경의 값을 복사하는 것으로 최적화를 대신하지 않는다. 성능을 좌우하는 주기와
  단위, 해당 값을 선택한 근거 또는 측정이 필요한 가정을 YAML 주석에 간결하게 기록한다.

## 검증과 기록

- 저장소 루트에서 `uv run exp experiments/configs/<category>/<name>.yaml --dry-run`으로
  옵션·값·모델 경로를 확인한다. `--dry-run` 통과는 처리량이나 학습 성능 검증을 대신하지 않는다.
- 성능 변경은 동일 환경·worker 수·update 예산에서 측정한다. 컴파일·워밍업을 제외한 처리량,
  시작·평가·저장을 포함한 전체 시간, 학습 곡선·목표 성능 도달 시간을 구분해 기록한다.
- 검증 명령·실행 조건·diff·결과는 루트 지침에 따라 Git에서 제외된 `runs/`에 보관한다.
  측정하지 않은 값은 최적값으로 단정하지 않는다. 정식 테스트와 합격 기준의 소유권은
  루트 `AGENTS.md`를 따르며, 이 문서는 변경 권한을 추가하지 않는다.
